# smgen-store

`smgen-store` adds hosted checkout controls to an SMGen page. The published site contains static HTML, CSS, and provider-supplied browser code. It does not need an application server.

## Install the Plugin

```sh
npm install --save-dev smgen-store
```

Add it after any plugin that generates product pages:

```yaml
PLUGINS:
  - use: smgen-data-pages
    options:
      config: .smgen-data-pages.yaml
    watch:
      - .smgen-data-pages.yaml
      - data/products.csv
      - templates/product.md.php
  - smgen-store
```

The prepare hook scans authored pages and pages generated by earlier plugins. A failed checkout schema stops the atomic SMGen build before it replaces the published output.

## Describe a Product

Add the versioned store mapping to page frontmatter:

```yaml
---
title: SMGen Mug
storePage: true
plugins:
  smgen-store: true
store:
  schema: 1
  type: product
  id: MUG-001
  name: SMGen Mug
  description: A sturdy mug for long builds.
  price:
    amount: "24.00"
    currency: USD
  checkout:
    provider: hosted-link
    presentation: link
    url: https://example.com/checkout/smgen-mug
---
```

Keep `price.amount` quoted. The validator requires a positive decimal string and a three-letter uppercase currency code. The displayed price is descriptive. The checkout provider controls the amount the buyer is charged.

Place a checkout marker where the control should appear:

```markdown
::: {.smgen-store-checkout}
:::
```

The filter replaces each marker with accessible checkout markup. `checkout.label` can replace the default `Buy PRODUCT_NAME` text.

## Choose a Checkout Mode

Every mode requires an HTTPS fallback URL.

| Provider | Presentation | Public fields | Browser code |
| --- | --- | --- | --- |
| `hosted-link` | `link` | none | none |
| `stripe` | `link` | none | none |
| `stripe` | `embed` | `buyButtonId`, `publishableKey` | Stripe buy-button script |
| `paypal` | `link` | none | none |
| `paypal` | `embed` | `hostedButtonId`, `clientId` | PayPal hosted-buttons script and a small local initializer |
| `paypal` | `cart` | `merchantId`, `cartItemId` | PayPal cart script and a small local initializer |
| `square` | `link` | none | none |

Plain links add no JavaScript. The filter emits a provider script once per page only when an embed or cart marker needs it. A normal link remains available if provider initialization fails.

Stripe embed metadata looks like this:

```yaml
checkout:
  provider: stripe
  presentation: embed
  url: https://buy.stripe.com/example
  public:
    buyButtonId: buy_btn_example
    publishableKey: pk_live_example
```

Copy both public values from Stripe's Payment Link buy-button code. Stripe documents the current component and required domains in its [buy button guide](https://docs.stripe.com/payment-links/buy-button).

PayPal hosted button metadata uses values from its generated button code:

```yaml
checkout:
  provider: paypal
  presentation: embed
  url: https://www.paypal.com/ncp/payment/example
  public:
    hostedButtonId: EXAMPLE123
    clientId: EXAMPLE_PUBLIC_CLIENT_ID
```

For a PayPal cart, copy the merchant ID from the View Cart script and the product ID from the Add to Cart button:

```yaml
checkout:
  provider: paypal
  presentation: cart
  url: https://www.paypal.com/ncp/payment/example
  public:
    merchantId: MERCHANT123
    cartItemId: ITEM123
```

PayPal requires both Add to Cart and View Cart controls. Its [shopping cart guide](https://developer.paypal.com/payment-links-buttons/create-cart-button/) describes the generated values.

Square's Web Payments SDK needs a backend to charge the single-use token. Static sites should use a reusable link created in the Square Dashboard. Square distinguishes reusable Dashboard links from single-use API links in its [Checkout API pitfalls](https://developer.squareup.com/docs/checkout-api/common-pitfalls).

## Add Product JSON-LD

Store metadata does not replace normal page metadata. Add Schema.org data through SMGen's `jsonld` frontmatter:

```yaml
jsonld:
  "@context": https://schema.org
  "@type": Product
  sku: MUG-001
  name: SMGen Mug
  offers:
    "@type": Offer
    price: "24.00"
    priceCurrency: USD
    url: https://example.com/checkout/smgen-mug
    availability: https://schema.org/InStock
```

The example in `smgen-data-pages` emits this data from the same row as the checkout mapping.

## Validate Locally

Validate authored store pages without running Pandoc:

```sh
npx smgen-store validate pages
```

Generated pages exist only during a build, so `smgen build` remains the complete store check. A site can keep a short CI script:

```json
{
  "scripts": {
    "validate:data": "smgen-data-pages validate",
    "validate:store": "smgen-store validate pages",
    "check": "npm run validate:data && npm run validate:store && smgen build"
  }
}
```

The validator rejects unknown schema fields, unsupported provider modes, unquoted or malformed prices, non-HTTPS links, missing public identifiers, and credential-shaped fields or values. Do not place Stripe secret keys, PayPal client secrets, Square access tokens, or any other private credential in Markdown, YAML, CSV, or Git.

## Set a Content Security Policy

Link presentation needs no additional policy. Embedded controls need the domains used by their provider:

- Stripe: allow `https://js.stripe.com` in `script-src` and `frame-src`.
- PayPal hosted buttons: allow `https://www.paypal.com` in `script-src` and the provider domains used by the generated checkout frame.
- PayPal cart: allow `https://www.paypalobjects.com` in `script-src` and the provider domains opened by the cart.
- PayPal modes also need `'self'` in `script-src` for `/smgen-store/store.js`.

Test each provider's generated control and fallback link before publishing. Provider dashboards remain the source of truth for pricing, tax, shipping, inventory, payment state, refunds, and fulfillment.
